# Release note template

Use the app's actual version as the release title (for example, `Ace 1.2.0`). Include the release date and availability in the body. Use tags such as `ace-v1.2.0`; tags here identify community release notes, not application source builds. Mark beta releases as pre-releases.

Copy the sections below, remove empty sections and instructions, and replace every placeholder before publishing. Only describe verified shipped changes. Do not use automatically generated repository commit notes for app changes.

---

Released: YYYY-MM-DD

Availability: platform, rollout, and minimum supported versions where relevant

## New

- Describe a new capability and why it helps.

## Improved

- Describe a user-visible improvement.

## Fixed

- Describe a resolved problem in plain language.

## Known issues

- Describe any material limitation and workaround, if available.
